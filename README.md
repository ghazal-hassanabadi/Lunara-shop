# لونارا (Lunara) | فروشگاه آنلاین پوشاک زنانه

لونارا یک مینی‌فروشگاه فارسی و راست‌چین برای پوشاک زنانه است (صفحه‌ی اصلی + صفحه‌ی فروشگاه). این پروژه را برای تسک **ساخت مینی‌فروشگاه** نوشته‌ام: نمایش محصولات، جستجوی لحظه‌ای، فیلتر ترکیبی، منوی موبایل و سبد خرید کشویی با ذخیره در `localStorage`.

🔗 **مشاهده‌ی خروجی پروژه:** `https://ghazal-hassanabadi.github.io/Lunara-shop/`

---

## سایت چیست و چه کاری می‌کند؟

### صفحه‌ی اصلی (`index.html`)

صفحه‌ی معرفی فروشگاه است و کاربر می‌تواند کالکشن‌ها را ببیند، دسته‌بندی‌ها را مرور کند و پرفروش‌ترین محصولات را به سبد خرید اضافه کند.

- **نوار اعلان:** اطلاعات ارسال و ارسال رایگان.
- **هدر:** لوگو، منوی اصلی، کادر جستجو و آیکون‌های حساب کاربری، علاقه‌مندی‌ها و سبد خرید (با شمارنده‌ی تعداد).
- **اسلایدر اصلی (Hero):** سه اسلاید که خودکار عوض می‌شوند، با نقطه‌های قابل کلیک و دکمه‌ی «مشاهده محصولات».
- **دسته‌بندی‌ها:** پالتو، بارانی، هودی، بافت و شلوار با کارت‌های گرد.
- **پرفروش‌ترین‌ها:** چهار محصول اول از لیست محصولات + بنر تخفیف زمستانه.
- **مزایای خرید:** ارسال سریع، پرداخت امن، بازگشت کالا و پشتیبانی.
- **اینستاگرام و فوتر.**

### صفحه‌ی فروشگاه (`product.html`)

- لیست کامل محصولات به‌صورت کارت (عکس، نام، قیمت، قیمت قبلی خط‌خورده و برچسب درصد تخفیف).
- **جستجوی لحظه‌ای (با debounce):** همزمان با تایپ، لیست فیلتر می‌شود.
- **فیلتر ترکیبی:** دسته‌بندی (چندانتخابی)، محدوده‌ی قیمت و «فقط محصولات تخفیف‌دار». همه‌ی شرط‌ها با جستجو با هم اعمال می‌شوند (مثلاً «هودی» + «فقط تخفیف‌دار»).
- اگر چیزی پیدا نشود پیام «محصولی با این مشخصات پیدا نشد» نمایش داده می‌شود.
- در موبایل، پنل فیلتر با دکمه‌ی «فیلترها» باز و بسته می‌شود و دکمه‌ی «پاک کردن همه» همه‌ی فیلترها را برمی‌دارد.

### منوی موبایل

در صفحه‌های کوچک، دکمه‌ی همبرگری منو را باز و بسته می‌کند و آیکون آن بین «سه‌خط» و «ضربدر» عوض می‌شود. منو در این حالت‌ها بسته می‌شود:

- کلیک روی یکی از لینک‌ها
- زدن کلید `Escape`
- کلیک بیرون از منو
- بزرگ شدن صفحه تا اندازه‌ی دسکتاپ

### سبد خرید

1. با کلیک روی «افزودن به سبد خرید»، اطلاعات محصول از روی کارت خوانده می‌شود.
2. اگر محصول از قبل در سبد باشد، ردیف جدید ساخته **نمی‌شود** و فقط `qty` آن یکی زیاد می‌شود.
3. سبد در `localStorage` ذخیره می‌شود، پس با رفرش یا بستن صفحه از بین نمی‌رود.
4. عدد کنار آیکون سبد در هدر، مجموع تعداد کالاها را با عدد فارسی نشان می‌دهد.
5. با کلیک روی آیکون سبد، یک **کشوی سبد خرید** از کنار باز می‌شود که در آن می‌توان:
   - تعداد هر محصول را زیاد یا کم کرد (حداقل ۱)
   - محصول را حذف کرد
   - مجموع قیمت را دید
   - دید چقدر تا **ارسال رایگان** (خرید بالای ۱ میلیون تومان) مانده است
6. دکمه‌ی «ادامه‌ی خرید» کشو را می‌بندد تا کاربر به خرید ادامه بدهد.
7. اگر سبد خالی باشد، پیام «سبد خرید شما خالی است» نشان داده می‌شود.
8. اگر سبد در یک تب تغییر کند، تب‌های دیگر هم شمارنده را به‌روز می‌کنند (رویداد `storage`).

سایت **ریسپانسیو** است و برای زبان فارسی با `dir="rtl"` طراحی شده است.

### دسترس‌پذیری (a11y)

- تگ‌های معنایی (`nav`، `main`، `article`، `dialog`، `fieldset`، `legend`) و `aria-label` برای دکمه‌های آیکونی
- `aria-expanded` و `aria-controls` برای منوی موبایل و پنل فیلتر
- `role="status"` برای پیام «محصولی پیدا نشد» و `aria-live` برای مجموع سبد
- کشوی سبد با `<dialog>` ساخته شده و با `Escape` بسته می‌شود، و بعد از بستن فوکوس به دکمه‌ی سبد برمی‌گردد
- بعد از تغییر تعداد در سبد، فوکوس کیبورد گم نمی‌شود

- Tailwind CSS (نسخه‌ی ۴)

- `localStorage`

رنگ‌های برند در فایل ورودی Tailwind (`src/input.css`) تعریف شده‌اند و با کلاس‌هایی مثل `bg-wine` و `text-ink` در کل پروژه استفاده می‌شوند:

| نام رنگ | کاربرد |
|---|---|
| wine | رنگ اصلی برند (دکمه‌ها، برچسب‌ها، فوتر) |
| cream | پس‌زمینه‌ی صفحه |
| sand | پس‌زمینه‌ی کارت‌ها و کادرها |
| ink | رنگ متن |

## اجرای پروژه

چون از ES Modules استفاده شده، باز کردن مستقیم `index.html` کار نمی‌کند و باید با سرور محلی اجرا شود:

```bash
npx serve
# یا افزونه‌ی Live Server در VS Code
```

اگر کلاس‌های Tailwind را تغییر دادید:

```bash
npx tailwindcss -i ./src/input.css -o ./dist/output.css --watch
```

## نحوه‌ی کار JavaScript

**جریان داده:** `products.js` ← `render.js` ← `main.js`

### `main.js`
عنصر `#products-list` را پیدا می‌کند. اگر وجود داشت، مقدار `data-limit` را می‌خواند (۴ در صفحه‌ی اصلی، و در صفحه‌ی فروشگاه بدون محدودیت) و محصولات را رندر می‌کند. بعد `initMenu`، `initSlider`، `initSearch`، `initFilter`، `initCart` و `initCartDrawer` را اجرا می‌کند.

### `products.js`
آرایه‌ای از ۸ محصول با `id`، `name`، `price`، `oldPrice`، `discount`، `image` و `category`. چون استفاده از API اختیاری بود، داده را دستی نوشتم. برای افزودن محصول جدید فقط یک آبجکت به این لیست اضافه می‌شود.

### `render.js`
تابع `createCard` از روی داده‌ی هر محصول یک کارت HTML می‌سازد. برچسب تخفیف و قیمت خط‌خورده فقط وقتی نمایش داده می‌شوند که محصول `oldPrice` و `discount` داشته باشد. قیمت‌ها با `toLocaleString("fa-IR")` به عدد فارسی و سه‌رقمی فرمت می‌شوند. یک کد برای هر دو صفحه استفاده شده است.

### `search.js`
فقط در صفحه‌ی اصلی کار می‌کند: با زدن اینتر در کادر جستجو، کاربر به `product.html?q=...` می‌رود. خود جستجو در `filter.js` انجام می‌شود.

### `filter.js` و `debounce.js`
جستجو و فیلتر در یک تابع به نام `apply` جمع شده‌اند. چون هر دو روی یک لیست اثر می‌گذارند، اگر جدا نوشته می‌شدند با هم تداخل پیدا می‌کردند. `apply` هر بار شرط‌ها را از فرم می‌خواند و `products.filter` فقط محصولاتی را نگه می‌دارد که **با همه‌ی شرط‌ها** بخوانند:

```js
const result = products.filter((p) => {
  if (query && !normalize(p.name).includes(query)) return false;
  if (categories.length && !categories.includes(p.category)) return false;
  if (p.price < min || p.price > max) return false;
  if (onlyDiscount && !p.discount) return false;
  return true;
});
```

- **debounce:** با هر تایپ یا تغییر فرم، `apply` ۳۰۰ میلی‌ثانیه بعد از آخرین تغییر اجرا می‌شود، نه با هر حرف. برای لیست‌های بزرگ‌تر از رندر بی‌دلیل جلوگیری می‌کند.
- **یکسان‌سازی متن (`normalize`):** «ي» و «ك» عربی به «ی» و «ک» تبدیل می‌شوند و نیم‌فاصله مثل فاصله حساب می‌شود، تا «پارچه ای» هم «پارچه‌ای» را پیدا کند.
- **قیمت (`parsePrice`):** ارقام فارسی، عربی و انگلیسی و جداکننده‌ی هزارگان (`,` و `،`) پذیرفته می‌شود. مقدار خالی یا نامعتبر نادیده گرفته می‌شود و اگر «از» بزرگ‌تر از «تا» وارد شود، جابه‌جا می‌شوند.
- **امنیت:** متن جستجو فقط با `includes` مقایسه می‌شود و هیچ‌وقت وارد HTML نمی‌شود، پس کاراکترهای خاص (مثل `<` یا `%`) مشکلی ایجاد نمی‌کنند.
- پنل فیلتر در موبایل با `aria-expanded` باز و بسته می‌شود و `?q=` از صفحه‌ی اصلی هم همین‌جا خوانده می‌شود.

### `slider.js`
با `setInterval` هر ۳ ثانیه عکس و متن اسلاید عوض می‌شود. با نقطه‌ها می‌شود دستی جابه‌جا شد، با رفتن موس روی اسلایدر متوقف می‌شود و با خروج دوباره شروع می‌شود.

### `menu.js`
منوی موبایل را با `aria-expanded` باز و بسته می‌کند. از `matchMedia` برای تشخیص رسیدن به اندازه‌ی دسکتاپ استفاده می‌کند تا منو در آن حالت بسته شود.

### `cart.js`
منطق و داده‌ی سبد خرید اینجاست: `addToCart`، `changeQty`، `removeFromCart`، `getTotalCount` و `getTotalPrice`. افزودن به سبد با **event delegation** روی کل `document` کار می‌کند؛ یعنی یک شنونده‌ی کلیک برای همه‌ی دکمه‌ها، حتی کارت‌هایی که بعداً با JavaScript ساخته می‌شوند.

```js
const existing = cart.find((item) => item.id === product.id);
if (existing) existing.qty += 1;
else cart.push({ ...product, qty: 1 });
```

- خواندن از `localStorage` داخل `try/catch` است و داده‌ی نامعتبر فیلتر می‌شود، پس اگر داده خراب بود برنامه کرش نمی‌کند و سبد خالی برمی‌گردد.
- بعد از هر تغییر، رویداد سفارشی `cart:change` ارسال می‌شود. شمارنده‌ی هدر و کشوی سبد به این رویداد گوش می‌دهند و خودشان را به‌روز می‌کنند.

### `cart-drawer.js`
کشوی سبد را با تگ `<dialog>` و متد `showModal()` باز می‌کند. با دکمه‌ی بستن، کلید `Escape` یا کلیک روی پس‌زمینه‌ی تیره بسته می‌شود و در هر سه حالت اسکرول صفحه دوباره آزاد می‌شود.

- دکمه‌های `+`، `−` و حذف با event delegation روی لیست کار می‌کنند و از `data-cart-action` استفاده می‌کنند.
- بعد از هر تغییر لیست دوباره ساخته می‌شود، برای همین فوکوس کاربر کیبوردی به دکمه‌ی مشابه برمی‌گردد تا گم نشود.
- چون داده‌ی `localStorage` قابل دستکاری است، قبل از ورود به HTML با `escapeHtml` امن می‌شود.

## تست دستی

این سناریوها را قبل از تحویل دستی تست کرده‌ام:

| سناریو | نتیجه‌ی مورد انتظار |
|---|---|
| جستجوی خالی یا فقط فاصله | همه‌ی محصولات نمایش داده می‌شوند |
| جستجوی بدون نتیجه | پیام «محصولی پیدا نشد» |
| جستجو با کاراکتر خاص (`<b>`، `%`، `\`) | بدون خطا، بدون نتیجه |
| جستجو با «ي»/«ك» عربی یا «پارچه ای» با فاصله | محصول «پارچه‌ای» پیدا می‌شود |
| قیمت با ارقام فارسی (۱۰۰۰۰۰۰) | درست اعمال می‌شود |
| قیمت «از» بزرگ‌تر از «تا» | جابه‌جا می‌شوند |
| ترکیب دسته‌بندی + تخفیف + جستجو | فقط محصولات منطبق با هر سه |
| «پاک کردن همه» | همه‌ی محصولات برمی‌گردند |
| سبد خالی | پیام سبد خالی و پنهان شدن مجموع |
| رفرش صفحه با سبد پر | شمارنده و محتوای سبد حفظ می‌شود |
| دستکاری یا خراب کردن `lunara-cart` در `localStorage` | برنامه کرش نمی‌کند، سبد خالی می‌شود |

## استفاده از هوش مصنوعی

از هوش مصنوعی برای رفع باگ‌ها (مثلاً تأخیر در تغییر اسلاید، استایل دکمه‌ها)، مرور کد و کمک در نوشتن بخش‌هایی مثل فیلتر و کشوی سبد استفاده کردم. کد را خوانده‌ام و منطق هر بخش را می‌توانم توضیح بدهم.

## کارهای آینده

- دریافت محصولات از `fakestoreapi.com` با `fetch` و نمایش حالت لودینگ (Skeleton) و خطا.
- ذخیره‌ی **علاقه‌مندی‌ها** در `localStorage`.
- ساخت **صفحه‌ی تکمیل خرید** (آدرس و پرداخت) بعد از کشوی سبد.
- مرتب‌سازی محصولات (ارزان‌ترین، گران‌ترین، بیشترین تخفیف).
